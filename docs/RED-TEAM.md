# 发布前对抗式审核（v1.0）

所有条件未满足不得声明线上发布完毕。

| 审核角色 | 核心问题 | 发布阻断条件 | 处理 |
|---|---|---|---|
| 零基础店主 | 具体去哪点、做什么、完成凭证是什么？ | 只喊“做同城SEO/运营矩阵”没有步骤 | 26章每章给具体动作和交付物 |
| 真实经营者 | 播放量和成交是否被混为一谈？ | 用浏览量假装收入增长 | 工具按照利润与合格咨询设计 |
| 平台商家审核 | 抖音/点评/地图是否给了真实入口？ | 编造后台按钮、保证排名/曝光 | 只列官方入口；字段以当前页面为准 |
| 广告合规 | 是否虚假折扣/广告不披露/刷好评？ | 无广告标记、诱导评价、伪造客户 | 自营广告明显标注；不给违规SOP |
| 家庭隐私 | 能否反查亲属和店址？ | 含城市、店名、精确开业年、业务规模、客户记录 | 家庭案例只保留汽车服务业抽象场景 |
| 内容制作 | AI是否编造师傅故事/故障结论？ | 声称未核实案例是真实成交 | 内容分级，提示词强制事实库审查 |
| 数据分析 | ROI是否混淆营业额/利润？ | 分母为0显示错误、数字未标假设 | 显示不适用，预算和新增人力纳入成本 |
| 安全审查 | 是否上传证件、住址、客户原文？ | 公开敏感个人信息 | 只有匿名表格和案例，浏览器本地存储 |
| 代码审查 | 章节链接/手机视图/交互可用？ | 断链、JS语法错误、自动测试失败 | CI阻断发布，待线上浏览器核验 |

### 本版已完成的验证

- 由 `tests/` 自动核查来源字段、数量、相对链接、广告入口、敏感词黑名单与 HTML 文件完整性。
- Node 测试验证计算器公式、零分母、负利润与无效输入。
- 代码内无远端分析脚本、外部字体、上传逻辑或账号密码要求。

### 尚需在远程网站完成

- 创建并公开 GitHub 仓库；检查 Actions 验证和部署成功。
- 确认 Pages 地址 HTTP 200；抽查至少3个章节页、3个官方外链与商业链接。
- 用一台真机复核 375px 宽屏下的导航、计算器、30天导出/导入、复制按钮和微信内浏览器兼容性。
- 有实际经营者试用至少3章，记录打不开平台入口或理解有歧义的地方。

### 修复原则

不能确认的成效必须标注未知；不以宣传内容补数据空白。不把没有运行的测试写成已通过。每次版本更新对照上表重新审核。
